# Промпт для Claude Code

Положи в одну пустую папку (например `C:\ITTKI_Nazorat\`) 4 файла: `TZ_ITTKI_dastur.md`, `engine_reference.py`, `test_engine.py`, `test_invariants.py`. Открой эту папку в Claude Code и вставь текст ниже целиком.

---

Ты — senior Python-разработчик. Собери настольное приложение для Windows «ITTKI Nazorat» строго по техническому заданию в файле `TZ_ITTKI_dastur.md`. Это программная часть магистерской диссертации по учёту НИОКР, поэтому точность бизнес-логики важнее украшений.

## Исходные материалы в папке
- `TZ_ITTKI_dastur.md` — ТЗ. Прочитай целиком до начала работы.
- `engine_reference.py` — эталонный движок решений (IAS 38 + BHMS 11). Его логика проверена.
- `test_engine.py` — 22 эталонных сценария с ожидаемыми результатами.
- `test_invariants.py` — проверка инвариантов на 9 000 случайных проектов.

## Жёсткие правила
1. **Не меняй правила принятия решений** (раздел 4, M5 и таблицы M3/M4 в ТЗ). Если видишь ошибку или противоречие — остановись и напиши мне, не исправляй молча.
2. Движок — отдельный пакет `ittki/core/` без импортов UI. UI только вызывает движок.
3. Деньги — только `int` (сум), никаких float. Даты — `datetime.date`.
4. Весь текст интерфейса — на узбекском (латиница). Строки вынеси в `ittki/i18n/uz.py`, чтобы позже можно было добавить русский.
5. Коды счетов не зашивай в код — только в настройках (M12), значения по умолчанию из таблицы M6. Счёт 9410 для НИОКР не использовать нигде.
6. Каждый этап заканчивается зелёными тестами. Не переходи к следующему этапу, пока тесты не проходят.

## Стек
Python 3.11+, PySide6, SQLite (через `sqlite3`), openpyxl, python-docx, reportlab, pytest, PyInstaller. Окружение `venv`, зависимости в `requirements.txt`.

## Этапы

**Этап 1 — Движок (TDD).**
- Перенеси логику `engine_reference.py` в `ittki/core/engine.py` (dataclass-модели, `Settings`, `evaluate`, `schedule`, `carrying_amount`, `reconcile`), сохранив правила R0–R8 из раздела M5 ТЗ.
- Перенеси `test_engine.py` (22 сценария) и `test_invariants.py` в `tests/` без изменения ожидаемых чисел. В приложении `as_of` = сегодняшняя дата.
- Добавь `ittki/core/journal.py` (проводки M6) и `ittki/core/controls.py` (исключения E1–E10) с тестами на каждое правило.
- Покажи мне вывод `pytest -q`.

**Этап 2 — Хранение.**
- `ittki/db/` — схема SQLite из раздела 5 ТЗ, миграция при первом запуске, репозиторий загрузки/сохранения в модели движка.
- Журнал аудита (M11): каждое изменение пишется, удаление и правка журнала невозможны.
- Тест: сохранить проект S2 → загрузить → результат движка тот же.

**Этап 3 — Интерфейс (PySide6).**
- Окна из раздела 6 ТЗ. Карточка проекта с вкладками: Ma'lumot, Bosqichlar, Mezonlar, Xarajatlar, Qaror, Provodkalar, Amortizatsiya, Solishtirma.
- Во вкладке «Qaror» две колонки: IAS 38 | BHMS 11, цвет статуса, по каждой затрате — решение, причина и пункт стандарта.
- Ответ «Ha» нельзя сохранить без документа-доказательства (кроме случая, когда пользователь явно сохраняет как черновик — тогда срабатывает E1).
- Строгий деловой стиль: светлая тема, шрифт Segoe UI, без лишней анимации.

**Этап 4 — Отчёты.**
- Excel: график амортизации, сверка NAS ↔ IFRS, журнал затрат с решениями.
- Word (.docx): примечание к отчётности по BHMS 11 п.20 и IAS 38.118/126 (M9) на узбекском, цифры из движка.
- PDF: отчёт для аудиторского комитета (M10).
- Импорт затрат из Excel-шаблона (сгенерируй шаблон `templates/xarajatlar_shablon.xlsx`).

**Этап 5 — Демо-данные и упаковка.**
- 4 условных проекта из раздела 9 ТЗ, каждый с пометкой «Shartli misol». Кнопка «Demo ma'lumotlarni yuklash».
- `ITTKI_Nazorat.spec` и сборка `pyinstaller` в один exe; проверь, что exe запускается вне виртуального окружения (без установленного Python в PATH).
- `README.md` на русском: установка, запуск, сборка exe, запуск тестов.

**Этап 6 — Материалы для диссертации.**
- `docs/algorithm.md`: блок-схема движка решений в Mermaid (R0 сфера → статус критериев → R1–R8 → решение → проводка) и таблица соответствия K1–K7 ↔ IAS 38 ↔ BHMS 11.
- `docs/screenshots/`: скриншоты главных окон на демо-данных (сделай их программно, через `QWidget.grab()`).
- `docs/test_results.md`: таблица сценариев S1–S20 с фактическими результатами из pytest.
