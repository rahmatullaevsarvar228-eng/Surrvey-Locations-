# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Программа «ITTKI Nazorat» — учёт, капитализация и контроль расходов на НИОКР по BHMS 11 (2024) и IAS 38

Версия 1.2 (третья проверка: все ссылки сверены с первоисточниками) · 11.10.2026 · Автор диссертации: Raxmatullayev S.N. (ISFT)

---

## 1. Назначение

Программа помогает предприятию (пример — «Olmaliq KMK» AJ):
1. вести реестр проектов НИОКР и их стадий;
2. по каждому проекту проверять критерии признания нематериального актива **одновременно по двум стандартам**: национальному BHMS 11 (2024) и международному IAS 38;
3. автоматически разделять каждую затрату на «в расходы» и «капитализировать» с указанием причины и пункта стандарта;
4. формировать проводки, график амортизации, учитывать обесценение;
5. показывать расхождение NAS ↔ IFRS по каждому проекту;
6. генерировать текст примечания к отчётности (раскрытие информации);
7. выдавать отчёт об исключениях (нарушениях контроля) для аудиторского комитета.

## 4. Функциональные модули

### M1. Реестр проектов
Поля: код, название, **тип проекта** (`ITTKI` / `geologik qidiruv` / `buyurtma asosida (boshqa tashkilot uchun)`), подразделение, руководитель, дата начала, бюджет (сум), статус, флаг «стадии исследования и разработки можно разделить» (IAS 38.53), дата начала стадии разработки, дата готовности к использованию (акт приёмки), дата прекращения, срок полезного использования (мес.), **ожидаемая чистая выгода** (необязательно; для предела BHMS 11 п.13), примечание.
Список с фильтрами (статус, стадия, решение) и поиском.

### M2. Стадии (stage-gate)
Стадии: `tadqiqot` → `ishlanma` → `foydalanishga tayyor` или `to'xtatilgan`.
- Переход в `ishlanma` требует оценки критериев (M3) не позднее чем через 30 дней (настраивается), иначе исключение E3.
- Переход в `foydalanishga tayyor` требует дату акта приёмки и срок полезного использования (иначе E8).
- История переходов хранится, удалять нельзя.

### M3. Оценка критериев (единая шкала K1–K7)

| Ключ | Критерий (uz) | IAS 38 | BHMS 11 (2024) |
|---|---|---|---|
| K1 | Texnik jihatdan amalga oshirish mumkinligi | 38.57(a) | п.12, 2 |
| K2 | Yakunlash va foydalanish/sotish niyati | 38.57(b) | п.12, 3 |
| K3 | Foydalanish yoki sotish qobiliyati | 38.57(c) | — (отдельного критерия нет) |
| K4 | Kelajakdagi iqtisodiy naf / bozor mavjudligi | 38.57(d) | п.12, 4 |
| K5 | Yetarli texnik, moliyaviy va boshqa resurslar | 38.57(e) | п.12, 5 |
| K6 | Xarajatlarni ishonchli o'lchash | 38.57(f) | п.12, 1 |
| K7 | Mahsulot/jarayon aniq belgilangan (identifikatsiya) | 38.12 | п.12, 1 |

- Ответ: `Ha` / `Yo'q` / `Ekspert bahosi talab etiladi`.
- Для ответа `Ha` **обязателен документ-доказательство**: тип (buyruq, TEI, smeta, bozor tahlili, sinov dalolatnomasi, shartnoma…), номер, дата, файл (необязательно). `Ha` без документа считается невыполненным (E1).
- Оценки версионируются: новая оценка не затирает старую. Дата оценки = дата, с которой разрешена капитализация.

### M4. Журнал затрат
Поля: дата, сумма (целое, сум), категория, первичный документ, комментарий. Импорт из Excel по шаблону.

Категории и допустимость включения в стоимость актива:

| Категория | IAS 38 (38.66–67) | BHMS 11 (п.8–9) |
|---|---|---|
| salary — оплата труда персонала НИОКР | ✓ | ✓ |
| materials — материалы | ✓ | ✓ |
| services — услуги сторонних организаций | ✓ | ✓ |
| depreciation — амортизация ОС, используемых в НИОКР | ✓ | ✓ |
| direct_overhead — прямо относимые накладные | ✓ | ✓ |
| patent_amortization — амортизация патентов/лицензий | ✓ | ✓ |
| legal_registration — регистрация прав | ✓ | ✓ (п.7, 8(д) «прочие затраты») |
| selling — расходы на продажу | ✗ | ✗ (п.9) |
| general_admin — общие административные | ✗ | ✗ |
| training — обучение персонала | ✗ (38.67(c)) | ✗ (позиция автора: не относится к НИОКР по п.7) |
| other — прочие затраты, которые нельзя прямо отнести к проекту | ✗ | ✗ (п.7 требует прямой связи с НИОКР) |

### M5. Движок решений — правила (выполняются для каждого стандарта отдельно)

**R0. Сфера применения.** Тип `geologik qidiruv` → стандарт не применяется (IAS 38.2(c)–(d), IFRS 6; BHMS 11 п.4). Тип `buyurtma asosida` (риски и выгоды у заказчика) → не применяется (BHMS 11 п.5 → BHMS 4, 17; по IFRS — IFRS 15 / IAS 2). Решение «STANDART QO'LLANILMAYDI», затраты не классифицируются.

**Статус критериев на дату.** На любую дату действует **последняя** оценка, сделанная не позже этой даты. Статус: `bajarilgan` — все обязательные критерии = `Ha` и у каждого есть документ; `yo'q` — хотя бы один `Yo'q`; иначе `kutilmoqda` (есть «Ekspert» или `Ha` без документа). Обязательные: IAS 38 — K1–K7; BHMS 11 — K1, K2, K4, K5, K6, K7.

Каждая затрата классифицируется по первому сработавшему правилу:

| № | Условие | Решение | Обоснование |
|---|---|---|---|
| R1 | категория не допускается стандартом (таблица M4) | расход | IAS 38.67 / BHMS 11 п.8–9 |
| R2 | стадии нельзя разделить | расход | IAS 38.53 (в BHMS 11 не урегулировано — осторожность) |
| R3 | дата < начала стадии разработки | расход | IAS 38.54 / BHMS 11 п.10 |
| R4 | дата ≥ даты прекращения проекта | расход | — |
| R5 | дата ≥ даты готовности к использованию | расход | IAS 38.66, 38.20 |
| R6 | статус на дату затраты ≠ `bajarilgan` | расход, **без последующего восстановления** | IAS 38.65, 38.71 / BHMS 11 п.11 |
| R7 | иначе | капитализировать (Дт 0830) | IAS 38.57 / BHMS 11 п.12 |
| R8 | только BHMS 11: если задана ожидаемая чистая выгода и с этой затратой капитализированная сумма её превысит | часть до предела — капитализация, остаток — расход | BHMS 11 п.13 |

По IAS 38 предела при признании нет; если капитализированная сумма больше ожидаемой чистой выгоды — предупреждение «признак обесценения» (IAS 36.12).

Если в один день внесено несколько оценок, действует внесённая последней.

**Отмена критериев (новая оценка хуже прежней):**
- новые затраты идут в расходы (R6);
- IAS 38: предупреждение «признак обесценения — провести тест» (IAS 36.9, 36.12), автоматического списания нет;
- BHMS 11: если стал `Yo'q` — накопленная капитализированная сумма **списывается на дату оценки** (п.18); если `kutilmoqda` — капитализация приостанавливается с предупреждением. Восстановление списанного (п.19) — только вручную с обоснованием (v1).

**Решение по проекту:** `XARAJAT SIFATIDA TAN OLINADI` (ничего не капитализировано) · `KAPITALLASHTIRILADI` · `KAPITALLASHTIRILGAN, KEYIN HISOBDAN CHIQARILGAN` · `STANDART QO'LLANILMAYDI`.

**Амортизация:** линейная. Срок: IAS 38 — срок полезного использования; **BHMS 11 — не более 60 мес.** (п.16: меньший из срока полезного использования и пяти лет с момента признания). Начало — настройка: `auto` (по умолчанию: если акт приёмки 1-го числа — с этого месяца, иначе со следующего; IAS 38.97 «с момента готовности», BHMS 11 п.15 «с момента готовности к продаже/использованию»), `same_month`, `next_month`. Начисление в конце месяца; остаток от округления — в последний месяц; сумма амортизации всегда равна амортизируемой стоимости. Ликвидационная стоимость = 0 (IAS 38.100). Только конечный срок полезного использования (неопределённый срок в v1 не поддерживается). Если выгода потребляется при производстве других активов, амортизация относится на их стоимость (BHMS 11 п.17) — выбирается счёт дебета (2010/2510).

**Обесценение:** событие (дата, возмещаемая сумма).
- до готовности актива — стоимость снижается до возмещаемой суммы на дату события; амортизируется уже сниженная стоимость;
- после готовности — признаётся в конце месяца события после амортизации этого месяца (IAS 36.59), остаток делится на оставшиеся месяцы (IAS 36.63);
- для BHMS 11 то же событие отражается как снижение по п.18;
- IAS 38: для капитализированного, но не готового актива нужен тест **в каждом году** (36.10(a)); проверяется на 31.12 каждого закрытого года до даты «сегодня» → иначе E5.

**Прекращение проекта:** до готовности — списывается вся капитализированная сумма; после готовности — амортизация до месяца прекращения, затем списывается остаточная стоимость (IAS 38.112–113). Затраты после даты прекращения — в расходы.

### M6. Проводки (План счетов РУз, все коды редактируются в настройках)

| Операция | Дебет | Кредит |

| Затрата капитализируется | **0830** Nomoddiy aktivlarni xarid qilish | счёт источника* |

Счёт социального налога на оплату труда пользователь задаёт сам.

Все коды и названия сверены по Приложению 1 к **BHMS 21 (2024)** (lex.uz, docs/7282737). **9410 = «Sotish xarajatlari» — для НИОКР не использовать.** В плане счетов нет отдельного счёта для НИОКР; использование **0830** для затрат на собственную разработку — предложение автора (по названию счёт предназначен для «приобретения»): сверить с Инструкцией к BHMS 21 и научным руководителем. Все коды редактируются в настройках (M12).

### M7. График амортизации
Таблица по месяцам: период, остаток на начало, амортизация, обесценение, остаток на конец — отдельно IAS 38 и BHMS 11. Экспорт в Excel.

### M8. Сверка NAS ↔ IFRS
На выбранную дату: капитализировано, балансовая стоимость по каждому стандарту, разница и её причины (например: «K3 не выполнен — по IAS 38 в расходы, по BHMS 11 капитализировано»; «срок амортизации 96 мес. vs 60 мес.»). Сводно по всем проектам и по каждому. Экспорт в Excel.

### M9. Генератор примечания (Word .docx)
- **BHMS 11, п.20**: учётная политика по НИОКР; сумма НИОКР в расходах за период; методы амортизации; сроки/нормы; остатки на начало и конец с движением (капитализировано, амортизировано и списано, переведено в другие активы, восстановлено).
- **IAS 38.118** (по классу «созданные НМА»): сроки и методы, валовая стоимость и накопленная амортизация на начало/конец, сверка движения, статья ОПиУ с амортизацией; **IAS 38.126**: общая сумма НИОКР в расходах за период.
Текст на узбекском (латиница), цифры подставляются автоматически.

## 5. Модель данных (SQLite)
`projects` (включая тип проекта и ожидаемую чистую выгоду), `stage_events`, `assessments`, `assessment_answers` (ключ, ответ, документ), `evidence_documents`, `costs`, `impairment_events` (дата, возмещаемая сумма), `impairment_tests` (даты проведённых тестов), `settings`, `audit_log`. Проводки, графики и решения не хранятся, а каждый раз вычисляются движком.
Деньги — целые числа (сум), без float. Даты — ISO в БД, в интерфейсе `dd.mm.yyyy`.

## 6. Интерфейс
Окна: **Bosh sahifa** (сводка: проекты, капитализировано, в расходах, исключения) · **Loyihalar** · **Loyiha kartasi** (вкладки: Ma'lumot, Bosqichlar, Mezonlar, Xarajatlar, Qaror, Provodkalar, Amortizatsiya, Solishtirma) · **Nazorat** (исключения) · **Hisobotlar** · **Sozlamalar**.
В «Qaror»: рядом две колонки IAS 38 | BHMS 11, зелёный/красный/жёлтый статус, у каждой затраты причина и пункт стандарта.

## 7. Нефункциональные требования
- Windows 10/11, работает без интернета; один файл `ITTKI_Nazorat.exe` (PyInstaller).
- Python 3.11+, PySide6, SQLite, openpyxl, python-docx, reportlab (или экспорт PDF через Qt).
- **Движок решений — отдельный модуль без UI**, покрыт автотестами.
- Запуск < 3 с, проект с 1 000 затрат пересчитывается < 1 с.
- Резервная копия базы одной кнопкой.

## 10. Что программа НЕ делает и что нужно уточнить
- Не ведёт полный бухгалтерский учёт и не заменяет 1С; не рассчитывает налоги; не сертифицированное ПО.
- Не поддерживает: неопределённый срок полезного использования, амортизацию по объёму выпуска (BHMS 11 п.15 допускает метод по структуре выгод; в v1 — линейный), капитализацию затрат по займам (IAS 23), автоматическое восстановление списаний (BHMS 11 п.19, IAS 36.114) — только вручную.
- Позиция автора, обсудить с научным руководителем: (1) отсутствие в BHMS 11 отдельного критерия K3; (2) исключение категории `training` по BHMS 11 (в п.7–8 прямо не названа; в настройках можно включить, изменение пишется в журнал аудита); (3) применение подхода IAS 38.53 к BHMS 11; (4) использование счёта 0830 для собственных разработок.
- Порог признания НМА в 50 базовых расчётных величин (BHMS 7 п.6) для созданных активов программа не проверяет — применимость уточнить.
