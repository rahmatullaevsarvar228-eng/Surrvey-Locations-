# Контроль качества анкет (AnketaQC)

Десктоп-приложение для Windows: ищет статистические признаки фальсификации в
выгрузке полевого опроса (Kobo Toolbox или любая другая система) и помечает
подозрительные анкеты и интервьюеров для ручной проверки супервайзером.

Вход только по логину и паролю, который выдаёт администратор. Анкеты
приходят из Google-таблиц команд через сервер администратора (Google Apps
Script). Настройки проектов и история по волнам хранятся на компьютере
сотрудника: `%LOCALAPPDATA%\AnketaQC\anketa_qc.db`.

## Установка

1. Откройте вкладку **Actions** репозитория → последний успешный запуск
   **Windows build — AnketaQC** → скачайте артефакт `AnketaQC-windows`.
2. Запустите `AnketaQC-Setup-<версия>.exe`. Права администратора не нужны:
   программа ставится в профиль пользователя и создаёт ярлык на рабочем столе.
3. Вместо установщика можно взять `AnketaQC-portable-<версия>.zip`, распаковать
   его и запускать `AnketaQC.exe`.

Окно приложения рисуется через Microsoft Edge WebView2. В Windows 10 и 11 он
уже встроен. На старых системах без него поставьте
[WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/).

## Как устроен доступ

```
 Ваша Google-таблица «сервер» (Apps Script)       ← только вы (администратор)
   ├─ Пользователи: логин, команда, доступ вкл/выкл
   ├─ Источники: Google-таблицы с анкетами каждой команды
   └─ Журнал: входы, неудачные попытки, действия
          ▲
          │ логин + пароль, затем анкеты
          │
 Программа у сотрудника ── видит только таблицы своей команды
```

- **Вы** создаёте каждому сотруднику логин в разделе «Администрирование»
  и указываете его команду. Пароль генерируется и показывается один раз.
- **Выключили доступ** — программа у человека перестаёт работать при
  следующем обращении к серверу, даже если она открыта. Сброс пароля и
  удаление работают так же.
- **Команда сама подключает** свои Google-таблицы, куда поступают анкеты:
  даёт доступ «Читатель» адресу сервера и вставляет ссылку в программу.
  Другие команды эти таблицы не видят. Сами таблицы остаются закрытыми.
- **Автоматическая проверка.** Пока программа открыта, она по расписанию
  (по умолчанию каждые 15 минут) забирает новые анкеты из всех отмеченных
  таблиц проекта, перепроверяет всё и сообщает, сколько пришло новых анкет
  и сколько среди них брака.
- Без входа программа не работает.

### Установка сервера (один раз, ~10 минут)

1. Создайте новую Google-таблицу, например «AnketaQC — сервер». Никому её
   не открывайте.
2. **Расширения → Apps Script.** Удалите пример кода и вставьте весь файл
   [`server/Code.gs`](server/Code.gs). Сохраните.
3. Вверху выберите функцию **`setup`** → **Выполнить**. Google попросит
   разрешения: «Проверить разрешения» → ваш аккаунт → «Дополнительно» →
   «Перейти к проекту» → «Разрешить».
4. Откройте **Журнал выполнения** внизу. Там будет строка
   `Логин: admin   Пароль: …`. Сохраните пароль, это ваш вход
   администратора (потом его можно сменить кнопкой «Пароль»).
5. **Развернуть → Новое развёртывание → Веб-приложение.**
   «Выполнять от имени»: **Я**. «У кого есть доступ»: **Все**. Нажмите
   «Развернуть» и скопируйте ссылку вида `https://script.google.com/macros/s/…/exec`.
6. Запустите программу, раскройте «Адрес сервера» на экране входа, вставьте
   ссылку и войдите как `admin`.
7. Эту же ссылку и выданные логины раздайте сотрудникам.

Командам, которые подключают свои таблицы, нужно дать доступ «Читатель»
адресу вашего Google-аккаунта, от имени которого развёрнут сервер. Программа
сама показывает этот адрес на странице «Данные».

Если вы поменяли код сервера: «Развернуть → Управление развёртываниями →
изменить → Новая версия». Ссылка при этом не меняется.

## Проверка анкет руководителем

Программа сама только подсвечивает подозрительные анкеты. Окончательное
решение принимает **руководитель проекта** (роль задаёт администратор):

- раздел **«Проверка анкет»**: очередь «Нужно решить», фильтры «На
  перезвон», «Брак», «Принято»;
- по клику на анкету открывается окно: **почему** система её отметила
  (конкретные цифры + логика проверки) и **исходная строка** из
  Google-таблицы, где жёлтым выделены колонки, которые читала проверка;
- решение: **❌ Брак / ✅ Принять / 📞 На перезвон** с комментарием, по одной
  анкете или сразу для нескольких отмеченных;
- решения записываются на лист **«Решения ОТК»** в ту же Google-таблицу, откуда
  пришла анкета (ID, решение, причина, комментарий, кто, когда). Исходные
  данные Kobo не трогаются. Для записи у адреса сервера в этой таблице должно
  быть право **«Редактор»** (для чтения было достаточно «Читателя»);
- **«Чистая база»** (Excel): принятые анкеты и анкеты без замечаний со всеми
  исходными колонками. Нерешённые подозрительные — отдельным листом.

Сотрудники с ролью «Сотрудник» видят решения, но менять их не могут.

## Как пользоваться

1. **Вход.** Логин и пароль выдаёт администратор.
2. **Проект.** Для каждого проекта создайте свой (кнопка «+» слева). Колонки,
   пороги, правила, список значений и подключённые таблицы запоминаются
   для проекта.
3. **Данные.** Отметьте Google-таблицы проекта и нажмите «Загрузить и
   проверить». Если таблиц несколько, они объединятся в одну выгрузку
   с колонкой «Источник». Для разовой проверки можно перетащить Excel-файл.
4. **Колонки.** Частые названия (Device ID, старт, финиш, город, интервьюер)
   подставляются автоматически, их стоит один раз проверить.
5. **Пороги, открытые вопросы, правила.** Всё настраивается в окне, без
   правки кода.
6. **Результаты** разложены по разделам «Обзор», «Интервьюеры», «Анкеты»,
   «Города», «Ответы», «Повтор значения». Кнопка «Отчёт Excel» сохраняет
   полный отчёт.
7. **Сохранить волну** (внизу «Обзора»). Раздел «История» покажет, кто
   несколько волн подряд остаётся в жёлтой или красной зоне.

## Что проверяется

| Проверка | По умолчанию |
|---|---|
| Нет Device ID | брак |
| Одно устройство под несколькими кодами интервьюера (и наоборот) | предупреждение |
| Длительность меньше минимума (только у завершённых интервью) / больше максимума | брак |
| Интервал между стартами анкет на одном устройстве | брак |
| «Отдых»: время между концом предыдущей анкеты и началом следующей | брак |
| «Конвейер»: N+ анкет за окно в M минут на одном устройстве | брак |
| Доля одного интервьюера в городе, минимум интервьюеров на город, доля анкет без телефона | по городу |
| Анкета начата вне рабочего времени (время берётся местное, как в выгрузке) | предупреждение |
| Дубликат респондента: тот же телефон (последние 9 цифр) | брак |
| Дубликат респондента: те же имя и фамилия в том же городе | предупреждение |
| Глубина зондажа: в блоке открытого вопроса меньше ответов, чем минимум | предупреждение |
| Среднее число ответов интервьюера ниже X% медианы волны | брак |
| Пользовательские правила «если … то …» | задаётся в правиле |
| Повтор одного значения у интервьюера (по списку значений проекта) | отдельный статус |

**GPS-контроль** (раздел «GPS-контроль», карта в «Карта GPS»; логика из
`geo_app.py`). Работает, если на странице «Колонки» выбраны широта и долгота:

| Проверка | По умолчанию |
|---|---|
| Анкета дальше 2 км от ближайшей плановой точки своего города | предупреждение |
| Скопление: больше 20 анкет интервьюера в радиусе 1,5 км | предупреждение |
| 3+ анкеты интервьюера с координатами, совпадающими до метра (копирование, подмена GPS) | предупреждение |
| В анкете нет координат | предупреждение |

План точек: встроенный (14 городов, 97 точек) или свой из Excel (колонки
«Город», «Широта», «Долгота», «Название»). Для подложки карты нужен интернет,
точки и проверки работают без него.

Ответы-заглушки («не знаю», «999», «bilmayman» и т.п.) не засчитываются как
названное значение. Их список можно редактировать.

Статус интервьюера считается по доле брака в его анкетах: 🔴 от 50%,
🟡 от 20%, 🟢 ниже. Пороги меняются на странице «Пороги проверок».

## Для разработчика

```bash
cd qc_app
pip install -r requirements.txt
python run_app.py              # нативное окно
python -m anketa_qc --browser  # тот же интерфейс в браузере (удобно для отладки)
python -m pytest -q tests      # включает прогон server/Code.gs (нужен Node.js)
python tools/make_demo.py demo.xlsx   # демо-выгрузка с «нечестными» интервьюерами
```

Устройство:

- `anketa_qc/engine.py`: все проверки. Технический движок взят из
  `cheat_detector.py`/`main.py` без изменения логики.
- `anketa_qc/sources.py`: чтение Excel.
- `anketa_qc/remote.py`: клиент сервера доступа, объединение таблиц.
- `server/Code.gs`: сервер доступа на Google Apps Script.
- `tests/gas_harness.js`: прогон `Code.gs` в имитации сервисов Google.
  `tests/gas_server.js` поднимает её как локальный сервер для отладки
  интерфейса (адрес `http://127.0.0.1:<порт>/`).
- `anketa_qc/history.py`: SQLite с настройками проектов и историей волн.
- `anketa_qc/export.py`: оформленные Excel-отчёты.
- `anketa_qc/server.py`: локальный API для интерфейса.
- `anketa_qc/web/`: интерфейс (HTML/CSS/JS без внешних библиотек).
- `packaging/`: сборка PyInstaller, установщик Inno Setup, иконка.

Сборка на Windows вручную:

```bat
pip install -r requirements.txt pyinstaller
pyinstaller packaging\anketa_qc.spec --noconfirm
iscc packaging\installer.iss
```
