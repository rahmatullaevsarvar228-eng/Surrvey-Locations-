# Контроль качества анкет (AnketaQC)

Десктоп-приложение для Windows: ищет статистические признаки фальсификации в
выгрузке полевого опроса (Kobo Toolbox или любая другая система) и помечает
подозрительные анкеты и интервьюеров для ручной проверки супервайзером.

Вход только по логину и паролю, который выдаёт администратор. Анкеты
приходят из Google-таблиц команд через сервер администратора (Google Apps
Script). Настройки проектов и история по волнам хранятся на компьютере
сотрудника: `%LOCALAPPDATA%\AnketaQC\anketa_qc.db`.

## Установка

1. Откройте вкладку **Actions** репозитория → последний успешный запуск
   **Windows build — AnketaQC** → скачайте артефакт `AnketaQC-windows`.
2. Запустите `AnketaQC-Setup-<версия>.exe`. Права администратора не нужны:
   программа ставится в профиль пользователя и создаёт ярлык на рабочем столе.
3. Вместо установщика можно взять `AnketaQC-portable-<версия>.zip`, распаковать
   его и запускать `AnketaQC.exe`.

Окно приложения рисуется через Microsoft Edge WebView2. В Windows 10 и 11 он
уже встроен. На старых системах без него поставьте
[WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/).

## Что видно в программе

Открыли программу — она **сама** забирает свежие анкеты из таблиц проекта,
проверяет их и показывает сводку. Кнопка ↻ вверху — забрать новые анкеты
сейчас; пока программа открыта, это происходит и само (по умолчанию каждые
15 минут).

Вкладки сверху:

- **Сводка** — светофор проекта одной фразой, **сверка** («364 строки в
  таблице − 28 технических записей = 336 анкет = 42 брак + 28 проверить +
  266 норма» — видно, что ничего не потерялось и не посчитано дважды),
  анкеты по дням, последний день (кто работал, кто выполнил норму), причины
  брака, интервьюеры в зоне риска, брак по городам, отчёты.
- **По дням** — норма в день (руководитель вписывает число прямо на
  странице: 5, 6, 7…), таблица интервьюер × день: сколько засчитано (брак в
  норму не идёт), выполнена ли норма, кто не работал. Для выбранного дня —
  списки «не работали» и «ниже нормы». Необязательный список команды нужен,
  чтобы видеть и тех, кто за весь период ничего не прислал.
- **Интервьюеры**, **Брак** (почему, в каком блоке, где, кто), **Карта**,
  **Квоты**.
- **Анкеты** — все анкеты с причинами и решения руководителя (Брак /
  Принять / На перезвон). Фильтр **«На прозвон»** — выборка для контрольного
  прозвона, как принято в контроле качества: все «проверить» без решения и
  10% анкет без замечаний у каждого интервьюера.

Над графиками — фильтры **Регион · Город · Интервьюер · День**; на всё можно
нажать (город, причину, день, клетку таблицы). Цифры брака учитывают решения
руководителя. Редкие действия (источники данных, настройка проверки, Excel,
история, администрирование, пароль) — в меню «⋯».

**Отчёт Word** (кнопка вверху) — итог, графики, брак по регионам и городам,
причины простыми словами, блоки анкеты, карты GPS, интервьюеры, работа по
дням, квоты, выводы и место для комментария руководителя. Если выбран фильтр
— отчёт только по нему.

## Международные методы контроля качества

То, что применяют Pew Research, Всемирный банк и стандарт ISO 20252:

1. **Почти одинаковые анкеты** («percent match», Kuriakose & Robbins). Каждая
   анкета сравнивается со всеми остальными по ответам. Совпадает 85%+ —
   «проверить», 95%+ — брак «почти копия другой анкеты» (с номером той анкеты
   и интервьюером). Сравниваются анкеты, где общих вопросов не меньше 15.
2. **Выборка на прослушку** (как CARI). Во вкладке «Анкеты» фильтр «На
   прослушку»: все подозрительные анкеты без решения и случайная доля
   остальных у каждого интервьюера — 5%, у новых (первые 2 дня) 15%, у
   интервьюеров в зоне риска 20%. Выборка постоянная. Кнопка «Скачать список
   (Excel)» — с колонкой, куда группа мониторинга ставит «1»; эта «1» потом
   подхватывается сама.
3. **Необычные ответы интервьюера.** Ответы его респондентов сравниваются с
   остальными: сильно другое распределение (проверяется статистически —
   хи-квадрат с поправкой на число вопросов), слишком одинаковые ответы у
   разных респондентов, много «не знаю». Это сигнал для прозвона/прослушки,
   не брак. Видно во вкладке «Интервьюеры», в карточке интервьюера и в
   отчёте Word.
4. **Время по блокам анкеты.** Если в форме Kobo в начале блоков есть поля
   calculate с формулой `now()`, программа сама их находит, показывает
   обычное время каждого блока («Брак» → «Время по блокам») и отмечает
   анкеты, где блок пройден быстрее 25% обычного времени.
5. **Карточки интервьюеров (Word)** — для планёрки с супервайзером: статус,
   цифры, причины брака и что исправить, работа по дням, необычные ответы,
   анкеты для разбора, строка для подписи. Все сразу — «⋯ → Word: карточки
   интервьюеров»; одна — в карточке интервьюера.

Пороги всех методов — «Настройка проверки → Проверки → Международные методы».
На 4000 честных случайных анкетах ни один из методов не дал ложной тревоги.

## Как устроен доступ

```
 Ваша Google-таблица «сервер» (Apps Script)       ← только вы (администратор)
   ├─ Пользователи: логин, команда, доступ вкл/выкл
   ├─ Источники: Google-таблицы с анкетами каждой команды
   └─ Журнал: входы, неудачные попытки, действия
          ▲
          │ логин + пароль, затем анкеты
          │
 Программа у сотрудника ── видит только таблицы своей команды
```

- **Вы** создаёте каждому сотруднику логин в разделе «Администрирование»
  и указываете его команду. Пароль генерируется и показывается один раз.
- **Выключили доступ** — программа у человека перестаёт работать при
  следующем обращении к серверу, даже если она открыта. Сброс пароля и
  удаление работают так же.
- **Команда сама подключает** свои Google-таблицы, куда поступают анкеты:
  даёт доступ «Читатель» адресу сервера и вставляет ссылку в программу.
  Другие команды эти таблицы не видят. Сами таблицы остаются закрытыми.
- **Автоматическая проверка.** Пока программа открыта, она по расписанию
  (по умолчанию каждые 15 минут) забирает новые анкеты из всех отмеченных
  таблиц проекта, перепроверяет всё и сообщает, сколько пришло новых анкет
  и сколько среди них брака.
- Без входа программа не работает.

### Установка сервера (один раз, ~10 минут)

1. Создайте новую Google-таблицу, например «AnketaQC — сервер». Никому её
   не открывайте.
2. **Расширения → Apps Script.** Удалите пример кода и вставьте весь файл
   [`server/Code.gs`](server/Code.gs). Сохраните.
3. Вверху выберите функцию **`setup`** → **Выполнить**. Google попросит
   разрешения: «Проверить разрешения» → ваш аккаунт → «Дополнительно» →
   «Перейти к проекту» → «Разрешить».
4. Откройте **Журнал выполнения** внизу. Там будет строка
   `Логин: admin   Пароль: …`. Сохраните пароль, это ваш вход
   администратора (потом его можно сменить кнопкой «Пароль»).
5. **Развернуть → Новое развёртывание → Веб-приложение.**
   «Выполнять от имени»: **Я**. «У кого есть доступ»: **Все**. Нажмите
   «Развернуть» и скопируйте ссылку вида `https://script.google.com/macros/s/…/exec`.
6. Запустите программу, раскройте «Адрес сервера» на экране входа, вставьте
   ссылку и войдите как `admin`.
7. Эту же ссылку и выданные логины раздайте сотрудникам.

Командам, которые подключают свои таблицы, нужно дать доступ «Читатель»
адресу вашего Google-аккаунта, от имени которого развёрнут сервер. Программа
сама показывает этот адрес на странице «Данные».

Если вы поменяли код сервера: «Развернуть → Управление развёртываниями →
изменить → Новая версия». Ссылка при этом не меняется.

## Проверка анкет руководителем

Программа сама только подсвечивает подозрительные анкеты. Окончательное
решение принимает **руководитель проекта** (роль задаёт администратор):

- раздел **«Проверка анкет»**: очередь «Нужно решить», фильтры «На
  перезвон», «Брак», «Принято»;
- по клику на анкету открывается окно: **почему** система её отметила
  (конкретные цифры + логика проверки) и **исходная строка** из
  Google-таблицы, где жёлтым выделены колонки, которые читала проверка;
- решение: **❌ Брак / ✅ Принять / 📞 На перезвон** с комментарием, по одной
  анкете или сразу для нескольких отмеченных;
- решения записываются на лист **«Решения ОТК»** в ту же Google-таблицу, откуда
  пришла анкета (ID, решение, причина, комментарий, кто, когда). Исходные
  данные Kobo не трогаются. Для записи у адреса сервера в этой таблице должно
  быть право **«Редактор»** (для чтения было достаточно «Читателя»);
- **«Чистая база»** (Excel): принятые анкеты и анкеты без замечаний со всеми
  исходными колонками. Нерешённые подозрительные — отдельным листом.

Сотрудники с ролью «Сотрудник» видят решения, но менять их не могут.

## Квоты

Раздел «Квоты»: из чего состоит ячейка (город + любые колонки анкеты, для
возраста — интервалы вроде `18-24, 25-34, 35+`) и план по ячейкам. План можно
создать из данных («Строки из данных»), загрузить из Excel (колонки-признаки
и «План») или взять цифры по городам из GPS-плана. «Выполнение квот»
показывает по каждой ячейке: план, засчитано, под вопросом, брак, сколько
осталось добрать и перебор. Считаются только завершённые интервью.

## Балл риска и отчёт для заказчика

У каждой анкеты есть балл риска 0–100: несколько слабых сигналов
складываются, один сильный (конвейер, одинаковые координаты, дубликат
телефона) сразу даёт высокий балл. Очередь проверки отсортирована по нему,
у интервьюера показан средний балл.

«Для заказчика (Excel)» (карточка «Отчёты и история» на «Главной») — один Excel: сводка по волне,
причины брака, квоты, статусы интервьюеров и чистая база.

## Роли

| Роль | Что может |
|---|---|
| Администратор | всё, включая раздел «Администрирование» и все команды |
| Руководитель проекта | всё в своей команде + решения по анкетам |
| Сотрудник | проверки и отчёты своей команды, решения только видит |

## Как пользоваться

1. **Вход.** Логин и пароль выдаёт администратор.
2. **Проект.** Для каждого проекта создайте свой (кнопка «+» слева). Все
   настройки и подключённые таблицы запоминаются для проекта.
3. **Подключение данных.** Отметьте Google-таблицы проекта и нажмите
   «Загрузить и проверить». Если таблиц несколько, они объединятся в одну
   выгрузку с колонкой «Источник». Для разовой проверки можно перетащить Excel.
4. **Настройка проверки** — мастер из 7 шагов, делается один раз на проект:
   Колонки → Анкета (блоки, технические записи, завершённость) → Проверки →
   Открытые вопросы → Логика → GPS → Квоты. Частые названия колонок
   подставляются автоматически.
5. **Дашборды** — «Главная», «Брак: где и почему», «Карта GPS»,
   «Интервьюеры», «Выполнение квот». Кнопки «Отчёт Word» и «Excel» вверху.
6. **Сохранить волну** (внизу «Главной»). Раздел «История» покажет, кто
   несколько волн подряд остаётся в жёлтой или красной зоне.

## Что проверяется

| Проверка | По умолчанию |
|---|---|
| Нет Device ID | брак |
| Одно устройство под несколькими кодами интервьюера (и наоборот) | предупреждение |
| Длительность меньше минимума (только у завершённых интервью) / больше максимума | брак |
| Интервал между стартами анкет на одном устройстве | брак |
| «Отдых»: время между концом предыдущего интервью и началом следующей анкеты. Если перед анкетой было техническое задание (видео, фото), это не брак | брак |
| «Конвейер»: N+ анкет за окно в M минут на одном устройстве | брак |
| Доля одного интервьюера в городе, минимум интервьюеров на город, доля анкет без телефона | по городу |
| Анкета начата вне рабочего времени (время берётся местное, как в выгрузке) | предупреждение |
| Дубликат респондента: тот же телефон (последние 9 цифр) | брак |
| Дубликат респондента: те же имя и фамилия у того же интервьюера в том же городе (тёзки у разных интервьюеров — не дубликат) | предупреждение |
| Глубина зондажа: в блоке открытого вопроса меньше ответов, чем минимум | предупреждение |
| Среднее число ответов интервьюера ниже X% медианы волны | брак |
| Пользовательские правила «если … то …» | задаётся в правиле |
| **Две анкеты одновременно**: новая открыта, пока предыдущая на этом устройстве не закончена | брак |
| **Массовое открытие**: 3+ анкеты открыты на одном устройстве за 2 минуты | брак |
| **Пустой обязательный блок** у завершённого интервью | брак |
| **Сетка**: во всех вопросах блока-сетки один и тот же ответ | предупреждение |
| Повтор одного значения у интервьюера (по списку значений проекта) | отдельный статус |

**GPS-контроль** (раздел «GPS-контроль», карта в «Карта GPS»; логика из
`geo_app.py`). Работает, если на странице «Колонки» выбраны широта и долгота:

| Проверка | По умолчанию |
|---|---|
| **Не в своём городе**: координаты за чертой города из анкеты (справочник 38 городов Узбекистана или плановые точки + 2 км запаса) | брак |
| Анкета дальше 2 км от ближайшей плановой точки своего города | предупреждение |
| Скопление: больше 20 анкет интервьюера в радиусе 1,5 км | предупреждение |
| «Телепорт»: между соседними анкетами быстрее 60 км/ч (и дальше 1 км) | предупреждение |
| 3+ анкеты интервьюера с координатами, совпадающими до метра (копирование, подмена GPS) | предупреждение |
| В анкете нет координат | предупреждение |

План точек: встроенный (14 городов, 97 точек), свой из Excel (колонки
«Город», «Широта», «Долгота», «Название», «Радиус», «Квота») или прямо на
карте: клик — новая точка, точку можно перетащить, у каждой свой радиус и
квота анкет. На «Карте GPS» при выборе интервьюера рисуется его маршрут. Для подложки карты нужен интернет,
точки и проверки работают без него.

**Технические записи.** Если интервьюер не проводит опрос, а выполняет
задание (например, снимает видео, что поблизости нет рекламы), такая запись
не проверяется как интервью: длительность, интервалы, «конвейер», зондаж и
правила к ней не применяются, в квоты, норму и чистую базу она не идёт, а
место (GPS) проверяется. Интервью, начатое сразу после технического задания,
не считается «без перерыва». Программа находит такие записи **сама** — по
колонке вроде «Тип записи: Интервью / Техническое задание (видео)» или по
колонке с видео по заданию; в «Настройке проверки → Анкета» видно, что
найдено, и можно поправить. Распознаются и сокращения («ТЗ»), узбекские
варианты («Техник топшириқ», «texnik vazifa») и колонка с видеофайлом.

Если ТЗ заполняется **отдельной формой** — на другом листе или в другой
таблице, — укажите это в «⋯ → Источники данных»: у таблицы поле «ТЗ:» (лист с
техническими заданиями) или отметка «только ТЗ» (вся таблица — задания). Для
Excel — поле «ТЗ:» рядом с выбором листа. Тогда программа видит ТЗ в цепочке
записей устройства (даже без города в форме ТЗ), и интервью сразу после него
не считается «без перерыва». В окне анкеты видно, какая запись была перед
ней: интервью или техническое задание, и сколько минут прошло.

**Брак, отмеченный мониторингом.** Если группа мониторинга по аудиозаписи
ставит «1» в колонке вроде «Брак (аудиоконтроль)», программа находит её
сама. Такие анкеты не перепроверяются: сразу брак с причиной «Брак по
аудиоконтролю», не идут в норму, квоты и чистую базу и не ждут решения
руководителя. В «Настройке проверки → Анкета» видно, какая колонка найдена;
можно выбрать другую или указать, что «1» там означает не брак.

**Какой лист проверять.** В таблице бывает много листов (анкеты, свод,
мониторинг). Программа сама берёт лист, где есть нужные колонки (устройство,
старт, финиш, город, интервьюер), и запоминает его. Выбрать другой — в «⋯ →
Источники данных», у каждой таблицы список «Лист». Для Google-таблиц выбор
листа работает после обновления кода сервера (Code.gs, раздел «Если вы
поменяли код сервера»); без обновления читается лист, указанный при
подключении.

**Блоки анкеты.** У каждой проблемы указан блок, где она найдена: блок
вопросов (задаётся в «Настройке проверки → Анкета» или берётся из групп Kobo)
либо служебная область — «Время интервью», «GPS и место опроса»,
«Устройство и интервьюер».

Ответы-заглушки («не знаю», «999», «bilmayman» и т.п.) не засчитываются как
названное значение. Их список можно редактировать.

Статус интервьюера считается по доле брака в его анкетах: 🔴 от 50%,
🟡 от 20%, 🟢 ниже. Пороги меняются на странице «Пороги проверок».

## Для разработчика

```bash
cd qc_app
pip install -r requirements.txt
python run_app.py              # нативное окно
python -m anketa_qc --browser  # тот же интерфейс в браузере (удобно для отладки)
python -m pytest -q tests      # включает прогон server/Code.gs (нужен Node.js)
python tools/make_demo.py demo.xlsx   # демо-выгрузка с «нечестными» интервьюерами
```

Устройство:

- `anketa_qc/engine.py`: все проверки. Технический движок взят из
  `cheat_detector.py`/`main.py` без изменения логики.
- `anketa_qc/sources.py`: чтение Excel.
- `anketa_qc/remote.py`: клиент сервера доступа, объединение таблиц.
- `server/Code.gs`: сервер доступа на Google Apps Script.
- `tests/gas_harness.js`: прогон `Code.gs` в имитации сервисов Google.
  `tests/gas_server.js` поднимает её как локальный сервер для отладки
  интерфейса (адрес `http://127.0.0.1:<порт>/`).
- `anketa_qc/history.py`: SQLite с настройками проектов и историей волн.
- `anketa_qc/export.py`: оформленные Excel-отчёты.
- `anketa_qc/server.py`: локальный API для интерфейса.
- `anketa_qc/blocks.py`: блоки анкеты и технические записи.
- `anketa_qc/cities_uz.json`: справочник городов (центр, радиус, регион).
- `anketa_qc/word.py`: отчёт Word (python-docx + графики matplotlib).
- `anketa_qc/web/`: интерфейс (HTML/CSS/JS без внешних библиотек);
  `dash.js` — дашборды, графики и карта.
- `packaging/`: сборка PyInstaller, установщик Inno Setup, иконка.

Сборка на Windows вручную:

```bat
pip install -r requirements.txt pyinstaller
pyinstaller packaging\anketa_qc.spec --noconfirm
iscc packaging\installer.iss
```
